# PRD: PWA-приложение «Счета и акты»

**Версия:** 1.0
**Дата:** 13.11.2026
**Статус:** MVP реализован (архив `scheta-pwa.zip`), ожидается шаблон документов от пользователя

---

## 1. Цель продукта

Личное PWA-приложение для быстрого создания **счетов на оплату** и **актов выполненных работ**. Пользователь вводит сумму и выбирает покупателя, а приложение сразу формирует оба документа по шаблону. В документах автоматически меняются сумма, дата, номер и покупатель.

## 2. Пользователь

Один пользователь (владелец приложения), индивидуальный предприниматель или компания в Республике Казахстан. Многопользовательский режим и авторизация не нужны.

## 3. Основной сценарий

1. Пользователь один раз заполняет свои реквизиты в настройках.
2. Заранее добавляет покупателей.
3. Во вкладке «Создать» выбирает покупателя и вводит сумму.
4. Приложение создаёт **счёт на оплату** и **акт выполненных работ** с подставленными:
   - суммой (цифрами и прописью);
   - датой (по умолчанию сегодняшней);
   - номерами (автоинкремент);
   - данными покупателя.
5. Пользователь открывает документ и печатает его или сохраняет в PDF.

## 4. Структура приложения

| Раздел | Назначение |
|---|---|
| ➕ Создать | Форма создания счёта и акта одновременно |
| Счета на оплату | Раздел 1: список созданных счетов |
| Акты выполненных работ | Раздел 2: список созданных актов |
| Покупатели | Справочник покупателей |
| Настройки | Реквизиты, нумерация, НДС, резервная копия |

## 5. Функциональные требования

### 5.1. Создание документов
- Поля: покупатель (выбор из списка или ввод нового на месте), сумма (₸), дата, наименование услуги, № счёта, № акта.
- Номера подставляются автоматически (следующие по порядку), их можно изменить вручную.
- По одной кнопке создаётся пара документов: счёт и акт.
- После создания номера счёта и акта увеличиваются на 1.
- Сумма принимает пробелы и запятую как десятичный разделитель.

### 5.2. Счёт на оплату
- Предупреждающий текст об условиях оплаты.
- Образец платёжного поручения: бенефициар, БИН, ИИК, Кбе, банк, БИК, код назначения платежа.
- Заголовок «Счет на оплату № N от DD месяц YYYY г.».
- Поставщик, покупатель, договор.
- Таблица: №, наименование, кол-во, ед., цена, сумма.
- Итого, НДС («В том числе НДС X%» или «Без НДС»).
- «Всего наименований 1, на сумму … KZT», «Всего к оплате» прописью.
- Подпись исполнителя.

### 5.3. Акт выполненных работ (форма Р-1)
- Шапка: Приложение 50 к приказу Министра финансов РК от 20.12.2012 № 562, Форма Р-1.
- Заказчик и исполнитель с ИИН/БИН, договор, номер документа, дата составления.
- Таблица по форме Р-1 (8 граф): наименование, дата выполнения, сведения об отчёте, единица измерения, количество, цена, стоимость; строка «Итого».
- НДС, сумма прописью.
- Блоки «Сдал (Исполнитель)» / «Принял (Заказчик)» с подписями и М.П.

### 5.4. Разделы «Счета» и «Акты»
- Список: номер, дата, покупатель, сумма.
- Действия: открыть, распечатать или сохранить в PDF, удалить (с подтверждением повторным нажатием).
- Документ хранит снимок реквизитов на момент создания. Если позже изменить настройки, старые документы останутся прежними.

### 5.5. Покупатели
- Поля: название, БИН/ИИН, адрес, руководитель (для акта), договор (если не заполнен, берётся из настроек).
- Добавление, редактирование, удаление.

### 5.6. Настройки
- Реквизиты поставщика: наименование, БИН/ИИН, ФИО руководителя, адрес, банк, ИИК, БИК, Кбе, КНП, договор по умолчанию.
- Наименование услуги и единица измерения по умолчанию.
- Следующий № счёта и № акта.
- НДС: вкл/выкл, ставка (по умолчанию 12%).
- Резервная копия: экспорт и импорт JSON.

### 5.7. Сумма прописью
- На русском языке, в тенге и тиын. Пример: «Сто пятьдесят тысяч тенге 00 тиын».
- Правильный род и склонение: «одна тысяча», «две тысячи», «один миллион».

### 5.8. Печать
- Формат A4, на печать выводится только документ.
- Сохранение в PDF через системный диалог печати.

## 6. Нефункциональные требования

- **PWA:** manifest, service worker, иконки 192/512. Приложение устанавливается на телефон и компьютер и работает офлайн.
- **Хранение:** только `localStorage` браузера на устройстве. Сервера и синхронизации нет.
- **Без зависимостей:** один `index.html` без внешних библиотек.
- **Адаптивность:** удобно пользоваться с телефона.
- **Язык интерфейса:** русский.
- **Хостинг:** любой статический хостинг с HTTPS (например, Netlify Drop, GitHub Pages).

## 8. Модель данных (`localStorage`, ключ `scheta-data-v1`)

```
seller:   { name, bin, address, iik, bank, bik, kbe, knp, director, contract }
service:  { name, unit }
nextInv, nextAct: number
vat: boolean, vatRate: number
buyers:   [{ id, name, bin, address, contract, director }]
docs:     [{ id, date, sum, service, unit, invNo, actNo, vat, vatRate,
             seller{...}, buyer{...}, created }]
```

## 9. Ограничения и риски

- Данные хранятся в одном браузере. Если очистить данные браузера, они пропадут, поэтому нужна регулярная резервная копия.
- Данные не синхронизируются между телефоном и компьютером.
- Установка как приложения работает только по HTTPS.

## 10. Открытые вопросы и следующие шаги

1. **Получить шаблон документов от пользователя** и подогнать счёт и акт под него точь-в-точь (сейчас используются стандартные казахстанские формы).
2. Уточнить, нужны ли несколько позиций в одном документе (сейчас одна услуга).
3. Уточнить, нужна ли общая нумерация счёта и акта или раздельная (сейчас раздельная).
4. Возможные улучшения: сброс нумерации с нового года, поиск и фильтр по документам, отправка PDF в мессенджер, синхронизация между устройствами.
